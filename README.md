# PCB 走线审阅工作台（Circuit Board Rule Review）

一个**完全本地运行、零第三方依赖、无需账户**的 PCB 走线审阅工作台：可编辑的二维板图、
多铜层连接关系、网表预期，以及可解释的 DRC（设计规则检查）闭环。

打开应用即有一块内置示例板（4 个器件、过孔、顶/底层走线），其中特意内置了三类典型问题：

| 问题 | 示例位置 | 说明 |
| --- | --- | --- |
| **短接 short** | `LEDA` 的 `t11` 与 `LEDB` 的 `t12` 在顶层 (60,36) 接触 | 不同网络铜表面距离 = 0 |
| **净空不足 clearance** | `SIG` 的 `t2` 与 `GND` 的 `t14`（顶层） | 测得 0.082 mm，规则要求 ≥ 0.2 mm |
| **未布通 unrouted** | `XNET` 的 `t9`（顶）与 `t10`（底） | 两层投影相交，但中间没有过孔/贯通焊盘——**看着连着，实际断开** |

## 启动

要求 Node.js ≥ 20（只用内置模块，无需 `npm install`）。

```bash
npm start                 # http://localhost:5173
PORT=8080 npm start       # 自定义端口
```

数据默认写入 `./data`（原子写入、不可变版本快照）。可用 `PCB_DATA_DIR` 改变位置。

## 测试

```bash
npm test
```

38 个测试，包含：

- **几何单测**：带宽度走线（胶囊）、圆/矩形焊盘之间的精确表面距离、边缘接触判定；
- **检查引擎单测**：层间不连通、过孔/贯通焊盘搭桥、短接、净空测量值、同网络名不代表连通、
  局部修改不改变无关网络的对象身份与结论、不完整设计被拒绝、内容哈希与键顺序无关；
- **端到端 HTTP 测试**（`test/api.test.js`）：真实启动服务，走完
  **打开示例板 → 检查 → 编辑 → 保存 → 刷新重开 → 旧版报告取回 → 版本冲突 409 → 接续保存**
  的完整路径，并断言层间连通、网络归属、间距结论和冲突行为。

## 操作

- **网络面板**：点网络名，画布按连通岛高亮该网络在顶层/底层的实际连接范围；
- **问题列表**：点问题，画布聚焦相关对象，右侧显示触发规则、所在铜层、**两处具体对象**、
  测得距离 / 接触最近点坐标 / 连接依据；
- **编辑**：拖动走线/焊盘/过孔移动；右侧面板改网络、走线层、线宽、焊盘坐标/半径；
  左上改净空规则；
- **运行检查 (R)**：把当前画布内容发给服务端重新计算。计算期间旧版问题不标注在新坐标上；
- **保存新版 (Ctrl+S)**：乐观并发控制。两个窗口打开同一设计时，后保存者若基于过期版次会收到
  **409 冲突对话框**，可选择“以我的编辑接续最新版另存”或“放弃编辑载入最新版”，不会静默覆盖；
- **版本历史**：只读打开任意旧版次。旧报告的问题定位**只解释在该版次的几何快照上**，
  不会悄悄指到新版里同 id 的另一个对象。

## 数据模型与单位

所有坐标、线宽、半径、净空均为 **毫米 (mm)**。画布缩放仅改变显示，不参与服务端几何结论。

```jsonc
{
  "formatVersion": 1,
  "unit": "mm",
  "board": { "width": 80, "height": 50 },
  "layers": ["top", "bottom"],
  "rules": { "clearance": 0.2 },
  "objects": [
    { "id": "p1", "type": "pad", "component": "U1", "pin": "3V3",
      "x": 10, "y": 10, "shape": "circle", "r": 0.8, "holeRadius": 0,
      "net": "3V3", "layers": ["top"] },
    { "id": "v1", "type": "via", "x": 14, "y": 26, "r": 0.6, "drill": 0.3,
      "net": "GND", "layers": ["top", "bottom"] },
    { "id": "t1", "type": "trace", "net": "3V3", "layer": "top",
      "width": 0.5, "points": [[10, 10], [24, 10]] }
  ]
}
```

- 网表预期由焊盘的 `net`（`component`/`pin`）声明；
- `holeRadius > 0` 的焊盘与 `via` 一样**贯通两层**；
- 不完整设计（缺网络、非正数线宽/净空、坏单位、id 重复等）返回 **422**，
  错误带 `objectId`，前端保留用户编辑内容并列出无法检查的对象。

## 连接与检查规则（后端）

1. **同层接触才导通**：两对象在同一铜层上的铜表面距离 ≤ 1e-6 mm 时合并到同一连通岛
   （并查集）。线端贴着焊盘边缘（表面相切）计为连接。
2. **跨层不自动导通**：不同铜层的投影相交/重叠不合并；只有**同一对象跨越两层**
   （过孔、插件贯通焊盘）才能搭桥。跨层投影接触但分属两岛的同网络铜段，会作为
   “未布通”的判断证据列出。
3. **短接**：不同网络在同层表面接触（距离 0）。
4. **净空**：不同网络同层表面间隙 `0 < d < rules.clearance`，报告给出最近点与测量值；
   不同层之间不做净空检查。
5. **未布通**：同一网络名下的焊盘分布在多个连通岛，或存在接不到任何焊盘的铜岛。
   网络名相同只是预期，不是电气连接。

板上铜形状与检查结果来自**同一份设计内容**：检查报告携带 `revisionId` 与 `contentHash`
（规范化 JSON 的 SHA-256，键排序与数组顺序固定）。前端只在当前画布内容哈希与报告一致时
才把问题画到图上。

## HTTP 接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/designs` | 设计列表 |
| GET | `/api/designs/:id/head` | 最新已保存快照（版次 + 设计） |
| GET | `/api/designs/:id/revisions` | 版次历史 |
| GET | `/api/designs/:id/revisions/:rev` | 不可变旧版快照 |
| POST | `/api/designs/:id/check` | 检查（可含未保存内容，按内容哈希缓存） |
| PUT | `/api/designs/:id/save` | 保存新版，乐观锁 `{design, baseRevisionId}` |
| GET | `/api/designs/:id/reports/:contentHash` | 取回某内容版本的检查报告 |

## 代码结构

```
server.js              HTTP 服务 + 静态文件 + 路由
backend/design.js      数据模型、内置示例板、完整性校验、规范化哈希
backend/geometry.js    纯几何（mm）：胶囊/圆/矩形表面距离
backend/check.js       连接（并查集）+ 短接/净空/未布通检查引擎
backend/storage.js     原子持久化、不可变版本、乐观并发、报告缓存
public/                无框架 SVG 画布前端（index.html / app.js / style.css）
test/                  node:test 测试（几何、引擎、HTTP 端到端）
data/                  运行时生成（已 gitignore）
```
